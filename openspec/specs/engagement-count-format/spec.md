# engagement-count-format Specification

## Purpose

规定 App 与 Pack 互动计数（浏览、下载、点赞）在界面上的紧凑数字展示，使所有已展示这些数字的表面共用同一套规则：小值保持整数，大值用一位小数的 `K` / `M` / `B`，不加 `+`。

## Requirements

### Requirement: 互动计数使用紧凑单位

凡向用户展示 App 或 Pack 的浏览、下载或点赞次数时，系统 MUST 把精确整数值格式化为紧凑标签后再显示。小于 1000 的值 MUST 显示为不带单位、不带 `+` 的十进制整数（含 `0`）。大于或等于 1000 且小于 1,000,000 的值 MUST 以千为单位，保留一位小数并去掉末尾 `.0`，后缀为 `K`（例如 `1000` 为 `1K`，`12400` 为 `12.4K`）。大于或等于 1,000,000 且小于 1,000,000,000 的值 MUST 以百万为单位，同样一位小数并去掉 `.0`，后缀为 `M`。大于或等于 1,000,000,000 的值 MUST 以十亿为单位，后缀为 `B`。若按当前单位四舍五入到一位小数后系数为 `1000`，系统 MUST 升到下一单位（避免 `1000K`）。系统 MUST NOT 在标签上附加 `+`。本规则 MUST 同时用于终身计数与周榜窗口计数。非数字或缺失值的处理保持各表面既有缺省（通常显示 `0`）。本规则 MUST NOT 改变分页或目录「共 N 条」等非互动计数字段。

#### Scenario: 千以下保持精确整数

- **WHEN** 某项互动计数的精确值为 `0`、`428` 或 `999`
- **THEN** 界面 MUST 分别显示 `0`、`428`、`999`，且 MUST NOT 附加单位或 `+`

#### Scenario: 千与百万使用一位小数

- **WHEN** 某项互动计数的精确值为 `1000`、`12400` 或 `1500000`
- **THEN** 界面 MUST 分别显示 `1K`、`12.4K`、`1.5M`

#### Scenario: 不用商店下限档

- **WHEN** 某项互动计数的精确值为 `12400`
- **THEN** 界面 MUST 显示 `12.4K`，MUST NOT 显示 `10K+`、`12K+` 或 `1500K`

#### Scenario: 所有互动表面共用规则

- **WHEN** 用户在 App 详情、Pack 详情、Like 控件、货架或 Pack 卡片终身三项、周榜卡或首页 carousel 上看到浏览、下载或点赞数字
- **THEN** 同一精确值 MUST 格式化为同一标签
